# الركائز البشرية — الموقع ولوحة الإدارة

موقع عربي RTL مبني بـ HTML وCSS وJavaScript، مع Supabase لقاعدة البيانات والمصادقة والتخزين.

## الإعداد والتشغيل

1. أنشئ مشروع Supabase، ثم نفّذ كامل ملف [`supabase/schema.sql`](supabase/schema.sql) في SQL Editor.
2. أنشئ المستخدم الإداري الأول من **Authentication → Users** مع تعطيل التسجيل العام.
3. انسخ UUID للمستخدم الجديد ونفّذ استعلام Bootstrap الموجود في آخر `schema.sql` بعد استبدال `AUTH_USER_UUID` والاسم. لا تمنح الأدوار من المتصفح.
4. أضف Project URL وanon/publishable key إلى [`js/supabase-config.js`](js/supabase-config.js). هذا المفتاح مخصص للمتصفح؛ لا تضع service-role أو secret key في أي ملف للموقع.
5. أضف عنوان الموقع إلى قائمة Redirect URLs في إعدادات Auth. شغّل الموقع من خادم HTTP محلي، مثل `node assets/video/render-server.js`، ثم افتح `http://127.0.0.1:8765/index.html` أو `http://127.0.0.1:8765/admin/login.html`.

## مساعد العملاء والشكاوى

- شغّل `supabase/support-chat.sql` مرة واحدة في SQL Editor لإضافة جدول الشكاوى وسياساته.
- ضع Groq API key في `GROQ_API_KEY` داخل `.env` بجذر المشروع. لا تضعه في HTML أو JavaScript للمتصفح؛ خادم `render-server.js` يمنع تقديم ملفات `.env` كصفحات عامة.
- شغّل الخادم عبر `node assets/video/render-server.js`. أسئلة العملاء تُرسل من الخادم إلى Groq Chat Completions؛ مفتاح Groq لا يغادر الخادم.
- من زر «تقديم شكوى» في الشات، يطلب البوت وصف المشكلة ورقم الهاتف، ثم يُسجل الشكوى في Supabase. تظهر في لوحة الإدارة تحت «شكاوى العملاء»، مع الحالة والمسؤول وملاحظات المتابعة.
- الشكاوى لا يمكن للزوار قراءتها؛ يسمح RLS بإنشائها للزائر ومراجعتها لموظفي الطلبات والمدير فقط.

من Supabase **Authentication → Users** أنشئ حسابات الموظفين. الأدوار: `super_admin`، `content_manager`، `workers_manager`، `requests_manager`، و`admin` محدود. المدير الأعلى يضيف الأدمن من لوحة **الموظفون والصلاحيات** باستخدام User UID الذي يظهر في Auth. الأدمن يستطيع رفع PDF ومراجعة مسوداته الخاصة، وتحديث الطلبات والشكاوى، ولا يستطيع فتح محرر محتوى الموقع أو إدارة الموظفين. عند حفظ متابعة طلب أو شكوى يُسجل حساب الموظف المسؤول ويظهر اسمه في السجل ولوحة المدير. الوصول للبيانات يقيّده RLS حسب الدور.

للمشروعات التي طُبّق عليها `schema.sql` سابقًا، شغّلي ملف [`supabase/add-limited-admin-role.sql`](supabase/add-limited-admin-role.sql) مرة واحدة من Supabase **SQL Editor** لتفعيل الدور وسياسات RLS الجديدة. لا تفعّلي التسجيل العام؛ أنشئي حساب Auth أولًا ثم اربطيه كأدمن من لوحة الموظفين.

## وظائف المرحلة 3

- طلبات الموقع تُرسل إلى `customer_requests` دون حساب، ولا يستطيع الزائر قراءة الطلبات. يتابعها موظفو الطلبات ويحدثون الحالة والملاحظات.
- بطاقات العاملات تقرأ من `published_workers`، وهو عرض عام لا يتضمن الاسم أو مسار السيرة الذاتية. تظهر المنشورة والمتاحة فقط.
- رفع العاملات يقبل PDF فقط، يستخرج البيانات النصية لإنشاء مسودة بطاقة، ويرفع الملف إلى bucket خاص `worker-cvs`. فتح السيرة أو تنزيلها يستخدم رابطًا موقّتًا لموظفي إدارة العاملات والمدير فقط.
- يحاول النظام استخراج صورة المرشحة من أول صفحة في PDF ويحفظها في bucket خاص `worker-photos`. الاسم والعمر والجنسية والخبرة والسعر تظهر للعملاء بعد مراجعة الملف ونشره فقط. إذا تعذر استخراج الصورة أو لم يوجد السعر في السيرة، يضيف المسؤول الصورة/السعر أثناء مراجعة المسودة.
- للمشروعات التي طبقت المخطط السابق، شغّل `supabase/update-worker-cards.sql` مرة واحدة لإضافة حقول الصورة والسعر وسياسات الصور الخاصة.
- محرر الموقع يحفظ مسودة المحتوى منفصلة عن المحتوى المنشور. الصور تذهب إلى bucket عام `site-media`، بينما السير الذاتية خاصة.
- مدير المحتوى يستطيع رفع MP4/WebM حتى 50 MiB كفيديو خلفية للواجهة؛ شغّل `supabase/enable-site-video.sql` مرة واحدة إذا كان المشروع قد أُعد قبل إضافة الفيديو.
- عند غياب إعداد Supabase، تعمل المعاينة المحلية السابقة؛ لا تُرسل البيانات أو الملفات إلى خادم.

## ملاحظات الإطلاق

- بيانات التجربة القديمة تبقى في المتصفح المحلي ولا تُرفع إلى Supabase.
- استخراج PDF يعتمد على النص الموجود داخل الملف؛ PDF الممسوح كصورة يحتاج OCR ومراجعة بشرية.
- راجع سياسات RLS وقائمة Redirect URLs وبيانات الشركة والأسعار قبل نشر الموقع على نطاق عام.
- لا تُرفع مفاتيح سرية أو ملفات إنتاجية إلى المستودع.

## النشر على GitHub وVercel

- يحتوي `api/chat.js` على نقطة API الخاصة بالشات ومتوافقة مع Vercel Functions؛ لا تستخدم `render-server.js` على Vercel. الملف الأخير للتشغيل المحلي فقط.
- استوردي مستودع GitHub إلى Vercel كـ **Static Site** مع جذر المشروع الافتراضي، ولا تضيفي Build Command أو Output Directory.
- أضيفي Environment Variables في Vercel: `GROQ_API_KEY` (مفتاح جديد بعد إلغاء المفتاح الذي ظهر في المحادثة) و`GROQ_MODEL` بقيمة `openai/gpt-oss-120b`.
- إعداد Supabase للمتصفح موجود في `js/supabase-config.js` بمفتاح publishable. طبقي ملفات SQL المطلوبة على مشروع Supabase، وأضيفي نطاق Vercel إلى Redirect URLs في Auth.
- لا ترفعي `.env` إلى GitHub. الملف مستثنى عبر `.gitignore`؛ ارفعي `.env.example` فقط.
- بعد النشر، اختبري الموقع العام، نموذج الطلب، الشات، الشكوى، وتسجيل الدخول للوحة الإدارة. خزني الملفات السرية في إعدادات Vercel، ولا تضعي service-role key في المتصفح.

### آراء Google Maps

لجلب تقييمات الشركة مباشرةً، فعّلي Places API (New) في Google Cloud، ثم أضيفي `GOOGLE_PLACES_API_KEY` في إعدادات Vercel. يمكن ضبط `GOOGLE_PLACE_ID` اختياريًا لتثبيت صفحة الشركة الصحيحة؛ إذا لم يُضبط، يحاول الخادم العثور عليها بالاسم والعنوان. تعرض الصفحة بيانات التقييمات مع رابط Google Maps ونسبة التقييم. انتبهي إلى أن طلب حقل المراجعات عبر Places API يخضع لرسوم Google Maps Platform بحسب إعدادات حسابك.
